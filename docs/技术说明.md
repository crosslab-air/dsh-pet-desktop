# dsh-pet 桌面版 · 技术说明

把 [`PC2005-cloud/dsh-pet`](https://github.com/PC2005-cloud/dsh-pet) 的桌面桌宠**从 DSH 宿主里剥离出来**，
做成一个双击即运行、不依赖 DeepSeek Harness 的独立桌面宠物。

> 只想安装使用请看 [`../README.md`](../README.md)；
> 素材版权、溯源与许可边界见 [`../CREDITS.md`](../CREDITS.md)、[`../PROVENANCE.md`](../PROVENANCE.md)。

## 怎么用（软件形态，无命令行窗口）

1. **启动**：双击桌面上的 **`dsh-pet 桌宠`** 快捷方式。
   桌面没有？在**设置窗口 → 启动方式 → 创建 / 修复桌面快捷方式**点一下即可（首次启动也会自动创建）。
   启动后**不会出现任何命令行窗口**，桌宠直接出现在屏幕右上角。
2. **填 API Key**：在桌宠身上**右键 →「设置…」** 打开设置窗口，粘贴 Key，点「保存并验证」当场校验。
   （在 `https://platform.deepseek.com/api_keys` 新建一个专用 Key 更好。）
   **跳过这步也能用**，只是点桌宠会提示「缺少余额查询凭证」。
3. **设置窗口可以随时关掉** —— 它是个独立窗口，关闭后**桌宠照常运行**（已实测：关闭后桌宠窗口存活、
   本地服务正常）。托盘图标双击也能再打开它。
4. **退出**：在桌宠身上**右键 →「退出桌宠程序」**（或托盘图标右键 → 退出）。这才彻底关闭。
   任务管理器里**只有一个** `electron.exe` 进程（服务与桌宠同进程），不会有残留。

> 托盘图标（右下角鲸鱼）：左键双击 = 打开设置；右键 = 显示/隐藏桌宠 / 立即刷新余额 /
> 创建快捷方式 / 开机自启 / 打开数据目录 / 查看日志 / 退出。

### 交互

| 操作 | 行为 |
|---|---|
| **左键点击** | 播「点击回应」动画（5 段随机）+ **同时弹出余额气泡**（本版新增，非上游原生） |
| **右键** | 级联菜单：**打开 DeepSeek 用量页** / 查看余额 / 碎碎念 / 对话 / 回到初始位置 / 重载配置 / 动作点播 / **设置…** / **退出桌宠程序**（首项经本版改名改指，后两项为本版新增） |
| 拖拽 | 弹簧跟手；甩出去走抛物线 + 边缘反弹 + 落地摩擦，可跨屏 |
| 托盘图标 | 双击打开设置；右键：显示/隐藏桌宠 · 刷新余额 · 创建快捷方式 · 开机自启 · 打开数据目录 · 查看日志 · 退出 |

余额气泡沿用上游原生实现：`余额（峰/谷）¥xx.xx`，**峰红谷绿**，10 秒自动收起；
余额档位动画按已用百分比分 6 档（`余额-钱袋满溢` → `余额-分文不剩`）。

#### 为什么「打开网站」被改成「打开 DeepSeek 用量页」

上游这一项本来是打开 **DSH 网站**，实现是（`sprite.js:1063`）：

```js
window.petBridge.openDshSite(ORIGIN); // → 主进程 shell.openExternal(url) 交给系统默认浏览器
```

而 `constants.js:121` 定义 `const ORIGIN = new URL(CONFIG.configUrl).origin;` ——
**ORIGIN 就是宿主 web 服务的地址**。剥离 DSH 之后，我们注入的 `configUrl` 指向的是自己复刻的
**本地 JSON 接口服务**（`http://127.0.0.1:8231`），它只有 `/config`、`/state`、`/thumb/*`、
`/sound/*` 这些接口，**没有首页** —— `server.mjs` 的路由表里 `/` 落到兜底 404，浏览器打开
只有一张空白页（用户实测即此现象）。

处理办法（全部在 `patch-shell.js`，上游零改动）：把菜单树里那个叶子的 `label` 就地改掉，
并在 `onAction` 里抢在上游 `open-site` 分支之前**短路**它 —— 先用一个空叶子调一次上游
（只为让它照常关闭菜单），再自己 `openDshSite('https://platform.deepseek.com/usage')`。
**要换目标网址，改 `patch-shell.js` 顶部的 `OPEN_SITE_URL` 一行即可**（必须是 http/https）。

> 之所以不指向项目主页：本机 `github.com` 被代理拦截（CONNECT 502），点开同样打不开。

### 点击音效（本版新增）

上游 dsh-pet **完全没有音频能力**：106 段 webm 是纯 VP9（EBML 里只有 video track，无 audio track），
源码与 `config.jsonc` 里零 `audio` / `sound` 引用，`sprite.js` 反而显式把所有 `<video>` 设成 `muted`。
所以音效不能靠"给动画解静音"得到，必须独立播放。

音效**由本项目原创合成**，不取自任何第三方产品 —— 生成脚本 `scripts/make-sounds.py`
（纯 Python 标准库写 WAV，再用 ffmpeg 转 MP3）就在仓库里，可复现、也可自行改造音色。共 4 枚：

| 文件 | 用途 | 音色 | 设计时长 |
|---|---|---|---|
| `duck-press.mp3` | 按下 | 小黄鸭风格（上扬的"吱"） | 0.22 s |
| `duck-release.mp3` | 松开 | 小黄鸭风格（下行的"叽"） | 0.14 s |
| `dingdong-press.mp3` | 按下（第二套风格） | 高音"叮"（4 个分音） | 0.40 s |
| `dingdong-release.mp3` | 松开（第二套风格） | 低音"咚"（3 个分音） | 0.52 s |

播放链路：`patch-sound.js` 在**捕获阶段**监听 `pointerdown` / `pointerup`，落在命中区 `.pet-hit` 内
则分别播放 `<音效组>-press` 与 `<音效组>-release`；音频从本地服务 `/sound/<名>.mp3` 取
（页面 CSP 本就允许 `media-src http:`，无需改上游）。补丁只读事件、不拦截，不影响上游的拖拽/点击判定。

配置存在 `data\prefs.json` 的 `sound` / `vol` / `soundSet` 三项（默认 `true` / `0.68` / `duck`）。
在 **设置窗口 →「点击音效」** 里改，含开关 / 风格 / 音量 / 试听；**改动立即生效，不必重启** ——
主进程 `pushSoundConfig()` 会把新配置直接下发进已打开的宠物页面。

## 软件形态是怎么做到的（单进程、零控制台）

早期版本是「cmd 窗口 → node 启动器 → 起本地服务 → spawn Electron Helper」：
**两个进程 + 一个控制台窗口**，关掉那个窗口就等于杀掉桌宠 —— 这不是软件该有的样子。

现在改成：`electron.exe standalone\app` —— **本地服务就跑在 Electron 主进程里**，
上游 Helper 与它同进程。于是只剩**一个进程**、**零控制台**、**不再需要装 Node**。

### 三处必须守住的时序（踩过才知道）

1. **上游有 4 处「必须在 app ready 之前」的调用**（`autoplay-policy` / `setName` /
   `disableHardwareAcceleration` / `force-device-scale-factor`）。
   它们只有在 `require` 上游 `main.js` 时执行才有效 —— ready 之后再调用**静默失效**
   （表现为余额动画不自动播、透明窗黑边回归）。
   所以顺序必须是「**先同步 require 上游，再异步起服务**」。
2. 但 `DSH_PET_CONFIG_URL` 要等端口才知道 ⇒ 采用两条保险：
   - **预置**成首选端口 `8231`，而服务**默认就绑 8231**（占用才退到随机端口）⇒ 端口与预置值一致，竞态不存在；
   - 服务开启 `deferInitialBalance`（首查余额转后台），把「起服务」从 1~3 秒（等一次 HTTPS）
     压到**几十毫秒**，远快于 Electron ready。
   实测日志里 `forcedScaleFactor=1 primaryScale=1.25 petScale=1.25` 说明 DPI 那套全部准时生效。
3. **纯 Node 模式自救**：若进程被以 `ELECTRON_RUN_AS_NODE` 拉起（某些终端/宿主会把它透传给子进程），
   Electron 模块不注册，`require('electron')` 只返回一个字符串。该变量在**进程启动那一刻**生效，
   运行期删除无效 ⇒ 入口第一件事就是探测它，发现中招就用**净化后的环境**把自己重新拉起。

### 桌宠右键 → 主进程，走的是哪条路

渲染端拿不到 `electron` 模块（`contextIsolation: true`），上游 `preload.js` 也只暴露窗口控制原语，
而页面 CSP 本就允许 `http:`（它要靠它取 `/state` 与 `/thumb`）。所以：
**右键菜单 → `fetch(本地服务 /settings | /quit)` → 主进程**。
补丁 `patch-shell.js` 包住共享组件 `S.mountContextMenu`，往菜单树里追加两项 —— 上游零改动。

顺带留了两条自检：补丁启动时发一次 `/ping`（日志出现「控制通道自检通过」即通道正常），
以及 `/selftest`（打开设置窗口 → 关掉 → 断言桌宠仍在）。

### 快捷方式与图标

- **首次启动自动创建**：`app.whenReady()` 里若 `prefs.shortcutAtStart` 为真、且桌面尚无该快捷方式，
  延迟 2.5 秒调 `createShortcut()` 建好 —— 这是"装完之后只需双击桌面图标"的关键一步。
- 快捷方式由 `shell.writeShortcutLink` 创建，**已存在则 update、不存在才 create**
  （绝不用 replace 去覆盖别人的快捷方式）。目标是 `electron.exe`、参数是 `standalone\app`，
  **不经过 cmd**，所以双击它零控制台窗口。
- 图标不依赖任何图形库：用 Electron 的 `nativeImage` 把 `assets\logo.png` 转成
  16/32/48/64/128/256 六个尺寸，再按 ICO 容器格式（内嵌 PNG）手工拼出 `data\icon.ico`。
- **名字有一处历史遗留**：桌面快捷方式固定叫 **`dsh-pet 桌宠`**（常量 `SHORTCUT_NAME`），与仓库名一致；
  而程序内部显示名是 **`APP_TITLE = 'DS小鲸鱼'`** —— 沿用原桌宠的称呼，出现在托盘悬停提示与
  设置窗口标题栏。想让两者统一，改这两个常量即可，不影响功能。

### 日志

GUI 程序没有控制台，入口把 `stdout` / `stderr` 全部重定向到 **`data\app.log`**
（超过 2 MB 自动轮转为 `app.log.1`）。排查任何问题都先看它。

## 与上游的差异

### 代码层面：上游零改动

`dsh-pet\` 目录下**没有任何文件被修改或新增**。本版所有能力靠两层「包装」实现：

1. **`electron-main.cjs` 包装 `BrowserWindow.prototype.loadFile`**
   上游写的是 `win.loadFile('index.html')`（相对路径，依赖 appPath = helper 目录）。
   本入口在 `standalone\` 下，Electron 算出的 appPath 会变，相对路径必然解析失败 →
   包装时把 `'index.html'` 重写成 helper 目录的绝对路径。
   该包装在 `require` 上游 `main.js` **之前**打上；上游解构出的 `BrowserWindow`
   与本文件拿到的是同一个类对象，因此补丁必然生效。

2. **`patch-click-balance.js` 运行期注入**
   在页面 `did-finish-load`（全部脚本执行完毕）之后，用 `webContents.executeJavaScript`
   在**页面主世界**执行。`index.html` 的 CSP（`script-src 'self'`）拦不住它 ——
   上游自己的冒烟自检就是走这条路的。补丁做三件事：
   - 记录最近一次成功的余额状态（包 `applyBalanceLeaf` / `onBalanceTick`）；
   - 新增 `showBalanceBubbleOnly()`：只点亮气泡（内容仍由上游 `S.balanceBubbleView` 生成，
     峰谷着色与 10 秒收起全部沿用上游），**不碰动画通道**；
   - 包 `onClick()`：先跑原生点击回应，再出气泡，并让「点击触发的这次刷新」只更新气泡、不抢动画。

   若上游日后改了这些符号名，补丁会**静默降级**（退化成「点一下照播点击回应，余额走右键菜单」），
   不会报错、不会白屏。

### 配置层面：5 处差异

见 `standalone\config.jsonc` 文件头的 `[STANDALONE]` 标注：

| 字段 | 上游 | 本版 | 原因 |
|---|---|---|---|
| `pets[0].display` | `both` | `desktop` | 本版不接浏览器 overlay |
| `pets[0].whisperEnabled` | `true` | `false` | 无宿主 LLM，关闭**周期**自动碎碎念 |
| `pets[0].workStatusEnabled` | `true` | `false` | 无 DSH 会话事件源 |
| `notificationsEnabled` | `true` | `false` | 系统通知属浏览器半侧能力 |
| `eventsRefreshSec.balance` | `1800` | `300` | 本地服务按此周期刷新余额 |

### 为什么不注入 `DSH_PET_HOST_PID`

上游 `host-liveness.js` 会每 2 秒 `kill(pid, 0)` 探测「宿主还在不在」，宿主没了就自杀（issue #56）。
上游 `scripts/start-desktop.mjs` 恰好把这个变量设成了脚本自己的 pid，所以**它不能拿来当常驻启动器**。
本版**主动删除**该变量：`parseHostPid` 对「未设置」返回 `0`，而 `0` 的分支是「不做探测」。
同时删除 `DSH_PET_BRIDGE`（设了会走依赖 DSH 的 stdout 管道桥）与 `ELECTRON_RUN_AS_NODE`（issue #63）。

## 故障排查

| 症状 | 原因 / 处理 |
|---|---|
| 桌宠不出现 | 先看 **`data\app.log`**（仓库根下），日志末尾一般直接写着原因（配置解析失败 / 找不到 Electron / 端口异常） |
| 双击快捷方式没反应 | 看 `data\app.log`。若写着「已有实例在运行」，说明桌宠其实已经在了（去托盘里找那只鲸鱼） |
| 桌宠出现但点它没反应 | 日志里搜 `[standalone] 已启用：左键点击 = …`。没有该行 = 运行期补丁未注入 |
| 右键「设置…」「退出桌宠程序」点了没反应 | 日志里搜「控制通道自检通过」。没有该行 = 页面没连上本地服务（多半是端口被占，重启一次即可） |
| 点它提示「缺少余额查询凭证」 | 没填 Key：右键桌宠 →「设置…」→ 粘贴 → 保存并验证 |
| 点它提示「余额查询失败 HTTP 4xx」 | Key 无效或已过期，重新设置 |
| 显示「余额（峰）」但你认为是谷时段 | 上游 `deepseekPricingTier()` 只判「工作日时段 + 周六周日」，**不认法定节假日与调休补班**。要按节假日口径算需另行扩展 |
| 某段动画点了不播 | 该动画名在 `assets\webm` 里不存在。已知一处上游自带缺口：`碎碎念-对屏碎碎念` |
| 改了 `config.jsonc` 没生效 | 本版「重载配置」是空实现，请右键退出后重新启动 |
| 想清干净重来 | 删 `userdata\`（Chromium profile）即可，下次启动自动重建；`data\` 里是日志与偏好 |
| 端口冲突 | 服务**优先绑 8231**，被占用会自动改用系统分配的空闲端口（日志会写明），此时重启一次桌宠即可 |
